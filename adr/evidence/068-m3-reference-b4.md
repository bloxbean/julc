## `String.length`

Java's `length` counts UTF-16 code units. A script's string is Unicode text, so it holds no unpaired surrogate, and each scalar is 1 or 2 units. The count
reads the string's UTF-8 bytes: a continuation byte (`0x80..0xBF`) counts 0, a lead byte of `0xF0` or above counts 2, and any other byte counts 1. A constant
folds to Java's value, and JuLC rejects a literal with an unpaired surrogate (`JULC0093`).

Of the other `String` methods only `equals`, `+` and `getBytes()` compile, and each agrees with the JVM (`Adr068StringLengthTest`), including `"é"` against
`"é"`, which Java and Plutus both call different. `isEmpty`, `concat`, `isBlank`, `indexOf`, `substring`, `charAt`, `codePointAt`, `codePointCount`,
`compareTo`, `hashCode`, `equalsIgnoreCase` and `getBytes("UTF-16")` stop at compile time on both frontends, so none has this defect.

**Cost per UTF-8 byte.** Each byte is one step of a loop. `Builtins.lengthOfByteString(Builtins.encodeUtf8(s))` is the old lowering, measured on the JavaParser frontend
over strings of 0 and 100 scalars of each width. A constant string costs nothing at run time.

| Level | CPU per byte | Memory per byte | Old CPU per byte | Old memory per byte | Empty string, CPU / memory | Bytes added |
|---|---:|---:|---:|---:|---:|---:|
| `NONE`, `BASELINE` | 1,701,468 | 6,915 | 10,823 | 0.74 | +720,382 / +3,702 | +107 |
| `PV11_SAFE`, `PV11_COSTED` | 1,137,321 | 4,812 | 10,823 | 0.74 | +532,333 / +3,001 | +91 |

The cost is per byte, so a 4-byte scalar costs four times an ASCII one: at `PV11_SAFE`, 100 ASCII characters cost 114.7M CPU, and 100 of U+1F600 cost 455.9M.

## A method with no parameters

Both frontends lower a call of such a method to a read of its binder. The method is a value, so its `let` ran the body at script start: `c ? boom() : 2` failed
with `c` false, and a helper called twice traced once. `DelayedMethodPass` now makes a body that may fail a function of a unit, and each read of its binder a call.

**The pass runs on the assembled term,** because a call site can come before the method's body is lowered, so no call site knows whether the body may fail. By
assembly every body exists. `PirBackend` runs it for validators and `compileMethod` programs, after the literal folds and before the passes that move a conversion. So a method the
folds reduce to a constant stays shared and compiles to that constant, and those passes see a delayed read as the call it is. It carries source positions and debug provenance through what
it rebuilds. It adds no name a source can reach: the unit's binder is `#_`.

**`mayFail` is one function, and only what it can show is total is total:**

| Term | Total when |
|---|---|
| A constant, also one the folds left, a lambda, a bare builtin | Always |
| A variable | It is bound to a total term, in the term or by an enclosing field or method. A parameter holds what is known of its argument |
| `let`, `if` | Each part is total, and an `if`'s condition is a boolean |
| A listed builtin | Every argument is total, of the kind it takes, and at most 32,768 bytes |
| `ReplicateByte(n, b)` | Also, `n` is a constant in 0..8192 and `b` a constant in 0..255 |
| `ConstrData(t, ...)` | Also, `t` is a constant from 0 up |
| A constructor | Each field is total and of the kind its declared type encodes, and the tag is not negative |
| A call of a bound, non-recursive function, with all its arguments | Its body is total, with what is known of each argument in scope |
| A call of a recursive function, an unknown one or a parameter; a trace; anything else | Never |

The 32,768 is why `add`, `append` and the hashes are in the table with a bound: in Plutus 1.63.0.0 semantics variants D and E take integers up to 2^262143 and byte strings
up to 65,536 bytes (`Universe/Cardano.hs`), and fail past them. The size of a value is an upper bound the function adds up as it goes, and a hash has the size of its digest whatever its input, so a short input does not understate it. A reading walks a function once per argument, so a tree of calls is linear in its depth. `ConstrData` takes a `Word64` tag at those variants. A trace is not
a failure, but a `let` would show it at another time than Java does.

**What stays strict.** A body shown total stays one shared `let`, which nothing can tell from Java. `MerklePatriciaForestry.nullHash`, `nullHash2`, `nullHash4`, `nullHash8`,
`IntervalLib.always` and `never` keep their sharing and bytes. A library reached through a provider import (ADR-059) is linked by the backend as a definition, so a method with
no parameters there still runs once when the program starts, whether or not it is called, and fails the program if it fails. No such method in the stdlib's on-chain libraries is delayed, so this reaches only another library.
A read of a `@Param` field is delayed by the rule, though it cannot fail once bound: its binding is a decode, which is not total.

**A read is not a variable.** A handler that takes a read as having no effect would run the call twice, or out of order. `PirHelpers.isMethodRead` tells them apart by the method
namespace, and `failingBelow` and `swappedInOrder` bind such a read once. So does `PirHelpers.readOnce`, in the handlers that duplicate an operand: `abs`, `min`, `max`, `signum`, `compareTo` outside the `OP 0` form, and `Math.abs`, `max` and `min`, for an operand that holds a read anywhere, as `k().add(x)` and `k().abs()` do. Without it a chain of such methods, each reading the one below, doubles per level. Each handler evaluates its operands first and on every path, so the binding moves no failure, and an operand a branch does not reach is not run. A receiver with an effect is bound ahead of a bound argument, to keep Java's order. A call of a method with parameters is no read, so an operand with no read in it goes in as it did (T13). `if (e instanceof V v)` reads `e` for the test and for `v`, and goes through `readOnce` too, on both frontends. `Adr068DelayedMethodsTest` runs `take`, `drop`, `mod`, `>`, `>=`, `compareTo`, `abs`, `min`, `max`, `signum`, the `Math` delegates and patterns with a traced read as receiver, argument and both, with operands built on it, and chains of 24 levels of each, and of a random mix of them.

**MPF.** 18 programs at each of the 4 levels, 72 rows, each method that reads a `nullHash*` over proofs of branches, leaves and forks, with the pass off and on: **0 bytes and 0 budget differ.**

**What this costs.** Measured on the JavaParser frontend with the pass on and off, on the final code, `k` being `Builtins.unIData(Builtins.iData(7)).longValue()`, and `h` a Blake2b hash of a decoded
literal. The two profiles give the same row, so `BASELINE` and `PV11_SAFE` are one line. CPU and memory are for the whole program.

## The JVM

Each stub was read against Plutus **1.63.0.0** (commit `ac40fae4`), the release the repository pins, from the local checkout, with `git show`. The docs name the revision `f92b7d7d`, which is not an ancestor of that tag; `Bitwise.hs` and
`Builtins.hs` are the same in both.

| Stub | Plutus, `plutus-core/plutus-core/src/PlutusCore/` | JVM before | JVM now |
|---|---|---|---|
| `lessThanByteString`, `lessThanEqualsByteString` | `Default/Builtins.hs:1358`, `:1373`: `ByteString`'s order, unsigned | Signed | Unsigned |
| `andByteString`, `orByteString`, `xorByteString` | `Bitwise.hs:406`, `:435`, `:464`: from the first byte; padding keeps the longer's tail | From the last byte | From the first |
| `sliceByteString` | `Default/Builtins.hs:1301`: `take` and `drop` on `Int`s, which clamp | `(int)` | Clamps the `long`s |
| `indexByteString` | `Default/Builtins.hs:1323`: fails out of range | `(int)` | Throws |
| `consByteString` | `Default/Builtins.hs:1250`: `Word8` at variants C and E, which Plutus V3 uses | `(byte)` | Throws outside 0..255 |
| `replicateByte` | `Bitwise.hs:576`, `:85`: length 0..8192; `Default/Builtins.hs:2222`: a `Word8` | `(int)`, `(byte)` | Throws outside both |
| `decodeUtf8`, `decodeUtf8String` | `Default/Builtins.hs:1580`: `BS.isValidUtf8` | No check | Throws on invalid bytes |
| `verifyEd25519Signature`, in `JvmCryptoProvider` | `Crypto/Ed25519.hs`: fails on a key that is not 32 bytes or a signature that is not 64 | False, and a longer key read by its first 32 bytes | Throws on both; false for what then does not verify |

The Java VM agrees with each of these, read against the same files and run against the stubs at their edges (`Adr068ThrowingMethodsTest`). `JulcArrayList.take` and `drop` throw on any negative count, and both `get`s throw on an index past an `int`.

`JvmCryptoProviderTest` runs that row and each of the six hashes against the VM. The confirmation review's 432 differences on `Builtins.sha2_256` were the harness's: `julc-difftest` installs no `CryptoProvider`, so the JVM side throws `UnsupportedOperationException` before it hashes. With a provider each hash equals the script's at 9 sizes from 0 to 1,024 bytes. `verifyEcdsaSecp256k1Signature` and `verifySchnorrSecp256k1Signature` are not implemented by that provider, so they throw on the JVM, as the BLS stubs do.

**The JVM stubs do not model the 65,536-byte bound.** Variants D and E fail on a byte string past it (`Universe/Cardano.hs`), and a stub takes one. Of the stubs in the table above it is the one difference that remains. Outside that table, `constrData` takes a negative tag on the JVM and fails in the script: see the follow-ups.

## What this does not establish

- **Two differences stay,** as known issues: argument-first `prepend`, `contains` and `insert`, and duplicated operands in T13's family, which an operand built on a delayed read can be, as can the operand of an `instanceof`. See the follow-ups.
- **A provider import.** Its method with no parameters stays strict, as above. `mayFail` reads no library through a provider.
- **The size bound's precision.** `mayFail` adds sizes conservatively, so a total body near the bound may be delayed. It costs a little and is never wrong.
- **The 65,536-byte bound on the JVM,** as above.
- **Wrapped Java values.** `length` and the delay change no integer. T6 stands.
- **An on-chain run.** DevKit was not run. The harness's VM is the evidence. Scalus and Truffle ran only through `pairCaseTest` and the VM modules' tests.
- **Recorded evaluations.** Those whose script hash moved are no longer replayed against the recording, as the counts above say.
