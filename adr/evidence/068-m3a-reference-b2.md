# ADR-068 M3a: the reference change B1 → B2

Key-based Value methods, which both frontends compile, re-freeze the reference as **B2** (I1, "Reference changes"):

| Change | Commit |
|---|---|
| `ValuesLib.lovelaceOf`, `add`, `subtract` and `negate`, and `Value.lovelaceOf()`, are key-based | `f3e2c976`, `90b96e4a` |
| `ValuesLib.geqMultiAsset`, `leq` and `eq` compare over the keys of both Values, where a key one of them does not hold is 0 | `c712930e` |

This is one reference change, and only these methods move the reference with the gate off.

**The subset's rules are gate rules, not reference changes.** `JULC0094`, `JULC0095`, `JULC0098`, `JULC0099`, `JULC0100` and `JULC0101` rest on what javac resolved, so they run once, on javac's trees, after `analyze()` succeeds (`frontend/javac/SubsetRules.java`, `7259a010`): from `JavacGate.check` for a compilation on the default frontend, and from `JavacCompilation` on `frontend=JAVAC`. B2's files are written with the gate off, so they hold no rule:

| Default frontend, gate mode | The rules |
|---|---|
| `enforce`, the default | Reject, like javac's own errors |
| `report` | Written to the gate's report if `julc.javacGate.report` names a directory, else not written; the compilation goes on |
| `off` | Off, with the rest of the gate |

`CompilerOptions.setJavacGate`'s Javadoc says the same. The javac frontend has no gate to turn off, and applies the first four in every mode. `JULC0100` and `JULC0101` are about how the JavaParser frontend reads a name, so only the gate has them; the javac frontend binds a name to its element. So `adr068Lowering` shows a pin of a rule as a difference between the gate-off reference and `frontend=JAVAC`, with a D13 class of `Policy rejection`.

B1 is the M1c reference ([`068-m1c-reference-b1.md`](068-m1c-reference-b1.md)); its rows are not edited. B2's rows are new files beside
them, generated by the same tool over the same frozen corpus, from the code of `c712930e` and the tool of `50f3a18e`. Machine and toolchain as in M0's evidence.

`compileForDebug(String)`'s order and `compileMethod`'s log lines are put back as they were at B1 in `ee9ada30`. Neither moves a cell.

```sh

    > adr/evidence/068/ledger-b1-b2-diff.tsv

# The lowering gate's own reference, over its larger corpus (17,052 cases): see 068-m3a-lowering-foundation.md.
```

`adr068Baseline` now fails unless it writes these files, byte for byte. The one exception is the totals' `coverage` line, which counts
the rejection-site catalogue and grows with the javac frontend.

## The B1 → B2 differences, classified (D13)

[`068/ledger-b1-b2-diff.tsv`](068/ledger-b1-b2-diff.tsv) lists every differing case.

| Cases | What | Class |
|---|---|---|
| 132 | Cases that compile `ValuesLib` or call `Value.lovelaceOf()`: their bytes and source maps | Reference change: the methods above |
| 3 + 3 | The stdlib's `ValuesLib` and all-libraries rows, and the ledger's `Value.java` row, keyed by the new source; their old keys leave | Reference change: the sources above |
| 8 | New pins: 4 `.diffcase`s of `JULC0095` (a `@Param`, an instance field, a nested type's field, an initializer block) and 4 fixtures of `JULC0094`, `JULC0098` and `JULC0099` (`adr068/rule-fixtures`). With the gate off each compiles | New cases |
| 8 | Run rows of the 8 pins renamed `reject-*` for the gate's rules: the 7 of T31 and T33's `reject-packageless-pubkeyhash-record`. The same source and observations under a new name | Not a change of B2: a file renamed |
| 7 + 7 | The Blaster fixtures M1b rewrote, keyed by their new sources; their old keys leave. Same programs as at M1b, though two differ in bytes from B1's rows, 432 to 437 and 360 to 363 at `BASELINE`, which the new keys keep out of the diff | Not a change of B2: the corpus's fixtures are read from the tree |
| 21 + 33 | Provider rows, and specialization rows of part `instantiation`: their cells now digest a canonical text with every constant spelled out, where they digested a printer's | Tool correction (D13): `Adr068Ledger.describe` and `instantiate`. No source and neither frontend changed |

**The tool correction.** `describe` and `instantiate` digested `PirFormatter.format`, a printer for people, which prints `list [...]` and `data <...>`, so two libraries with different constants had one cell. They now digest `PirCanonical.of`, as the method digests do. The tool's change is `50f3a18e`, and the files follow at `d6c7db4d`. [`068/ledger-b1-b2-diff.tsv`](068/ledger-b1-b2-diff.tsv) holds each row's old and new cell. B1's files stand as they were.

**One move in the code, in no cell.** A declaration of several variables is read variable by variable (`7259a010`), so with the gate off `static byte a = 1, b[] = new byte[]{2, 3};` and `@Param static byte a, b[];` go from an `AssertionError` to `Unsupported primitive type: byte`. No corpus row holds one.

No other cell moves. No semantic observation of B1's 697 runs moves. The 132 have no run of their own, so that says nothing of them: each reads `semantics not observed`. No specialization moves apart from the row above, and no rejection apart from the inventory's two rows. The 4 `.diffcase`s add 4 runs: three give the JVM's value at every level, and the `@Param` one records `Crash` at every level: with the gate off it compiles to a program over the `@Param` as well, so the case's one argument fills that and leaves a function for a result. With the gate on, as the regression suite runs them, each is `JULC0095`.
