# ADR-068 M3a: the reference change B1 → B2

Key-based Value methods, which both frontends compile, re-freeze the reference as **B2** (I1, "Reference changes"):

| Change | Commit |
|---|---|
| `ValuesLib.lovelaceOf`, `add`, `subtract` and `negate`, and `Value.lovelaceOf()`, are key-based | `f3e2c976`, `90b96e4a` |
| `ValuesLib.geqMultiAsset`, `leq` and `eq` compare over the keys of both Values, where a key one of them does not hold is 0 | `c712930e` |

This is one reference change, and only these methods move the reference with the gate off.

**The subset's rules are gate rules, not reference changes.** `JULC0094`, `JULC0095` and `JULC0098` rest on what javac resolved, so they run once, on javac's trees, after `analyze()` succeeds (`frontend/javac/SubsetRules.java`, `7259a010`): from `JavacGate.check` for a compilation on the default frontend, and from `JavacCompilation` on `frontend=JAVAC`. B2's files are written with the gate off, so they hold no rule:

| Default frontend, gate mode | The rules |
|---|---|
| `enforce`, the default | Reject, like javac's own errors |
| `report` | Written to the gate's report; the compilation goes on |
| `off` | Off, with the rest of the gate |

`CompilerOptions.setJavacGate`'s Javadoc says the same. The javac frontend has no gate to turn off, and applies them in every mode. So `adr068Lowering` shows a pin of a rule as a difference between the gate-off reference and `frontend=JAVAC`, with a D13 class of `Policy rejection`.

B1 is the M1c reference ([`068-m1c-reference-b1.md`](068-m1c-reference-b1.md)); its rows are not edited. B2's rows are new files beside
them, generated by the same tool over the same frozen corpus, from the code of `c712930e`. Machine and toolchain as in M0's evidence.

`compileForDebug(String)`'s order and `compileMethod`'s log lines are put back as they were at B1 in `ee9ada30`. Neither moves a cell.

## Commands

```sh
# The frozen corpus: M0's recordings (cbdcbddb; in-repo, external and Elci), not a re-recording. corpus-b2.tsv lists
# corpus-b1.tsv's cases plus the 7 pins below. A recording holds the library text it was made with, so
# Adr068Corpus.REPLACED_SOURCES reads the recorded ValuesLib as the file in the tree, under each case's key.
# -Padr068.freeze writes the b2 files; without it the run compares with them.
./gradlew :julc-difftest:adr068Baseline -Padr068.corpus=<M0 recording> \
    -Padr068.corpus.external=<M0 external recording> -Padr068.corpus.elci=<M0 Elci recording> \
    -Padr068.external=<julc-examples clone at 22b4e00f> -Padr068.out=<dir> -Padr068.freeze=true --offline
python3 adr/evidence/068/compare-ledgers.py adr/evidence/068/ledger-b1 adr/evidence/068/ledger-b2 \
    > adr/evidence/068/ledger-b1-b2-diff.tsv

# The lowering gate's own reference, over its larger corpus (17,052 cases): see 068-m3a-lowering-foundation.md.
./gradlew :julc-difftest:adr068Lowering <its corpora> -Padr068.freezeReference=true -Padr068.freeze=true -Padr068.allowShrink=true
```

`adr068Baseline` now fails unless it writes these files, byte for byte. The one exception is the totals' `coverage` line, which counts
the rejection-site catalogue and grows with the javac frontend.

## The B1 → B2 differences, classified (D13)

[`068/ledger-b1-b2-diff.tsv`](068/ledger-b1-b2-diff.tsv) lists every differing case.

| Cases | What | Class |
|---|---|---|
| 132 | Cases that compile `ValuesLib` or call `Value.lovelaceOf()`: their bytes and source maps | Reference change: the methods above |
| 3 + 3 | The stdlib's `ValuesLib` and all-libraries rows, and the ledger's `Value.java` row, keyed by the new source; their old keys leave | Reference change: the sources above |
| 7 | New pins: 4 `.diffcase`s of `JULC0095` (a `@Param`, an instance field, a nested type's field, an initializer block) and 3 fixtures of `JULC0094` and `JULC0098` (`adr068/rule-fixtures`). With the gate off each compiles | New cases |
| 7 + 7 | The Blaster fixtures M1b rewrote, keyed by their new sources; their old keys leave. Same programs as at M1b | Not a change of B2: the corpus's fixtures are read from the tree |

No other cell moves. No semantic observation of B1's 697 runs moves, and no specialization or rejection. The 4 `.diffcase`s add 4 runs: three give the JVM's value at every level, and the `@Param` one records `Crash` at every level, because it is a compilation the harness has no `@Param` value for. With the gate on, as the regression suite runs them, each is `JULC0095`.
