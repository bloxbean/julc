# (its parameter hash checked against the recorded one, C23), source maps and disabledRules restored; the recorded

# error, an entry point it does not dispatch, a lookup other than the default registry or none, a cost profile

# corpus does any of these, so the outputs below, written by the round-3 runner, are what this runner writes. The run log starts with the SHA-256 of the compiler class files it
# loaded (C28). One JSON record per line.
# Comparator: compare_replay.py.txt. Validates every record against its kind and outcome; rejects unknown kinds and
# fields, orphan or missing higher-limit retries, and any harness error, even one both sides share (C20, C21); pins the
# 55 excluded case ids (SHA-256 b95d72fa4d276c2e5ac8875804dc500a869734430241f9347c39fd280dc82798, C27); compares
# matched higher-limit retries' semantics and budgets; counts bounded and inconclusive evaluations separately (C24).
# Round 4: it reads the corpus and requires each side's records to be exactly those the corpus calls for, and every
# digest to be 64 hex digits (C29); a one-sided exhaustion the higher limit resolves is reported as budget-only (C34);
# where both sides exhaust, a higher-limit exhaustion on one side only is inconclusive, as in the fixture oracle (C30).
# Round 5: where the transaction limit exhausted, the retry is each side's evidence; where an exhaustion persists, the
# case is inconclusive only if its traces are a prefix of the other side's, and otherwise a mismatch (C36); vectors
# and budgets must be JSON integers, not booleans (C40).
