# ADR-068 M0: the JavaParser frontend's baseline

The M0 evidence of [ADR-068](../068-javac-frontend-migration.md): the frozen corpus, the D13 ledger's reference
rows (compilations, specializations, harness runs and UPLC-only evaluations), the I2a rejection inventory and its
coverage gate, the D6 equality call-site scan and D4's accepted-divergence list. Everything in [`068/`](068/) is
generated by the commands below and sorted; nothing in it is edited by hand. This revision answers the M0 review
rounds (Claude F200–F204 and F210, Codex F300–F308 and F310–F317); [Review round 3](#review-round-3) lists what
changed in the last one.

Notes:

- **A case** is a `case.txt` (format 2: entry point, method, the stdlib lookup's identity, target, cost profile id
  and parameter hash, source-map flag, disabled rules, source and resolved-library digests) keyed by its SHA-256,
  with the levels it was compiled at, the instantiations made of it and the tests that compiled it. Its options
  are those the compilation resolved (its `CompilationContext`), never the caller's `CompilerOptions` read later,
  and a `JavaLibraryProvider` records its case once, at construction, and files every specialization under that
  case (F313). The lookup is `none`, `default:org.julclang.stdlib.StdlibRegistry` only for a registry that still
  holds the token `StdlibRegistry.defaultRegistry()` gives the registry it builds (any later registration clears
  it: equal keys, builder classes and requirements are not enough, because table-built builders share a class but
  capture different builtins, F310), or `custom:<class>:<fingerprint>` (F201/F300). The same inputs generated by the ledger (a
  `.diffcase`, a G0 or G1 program) have the same key, so every G0 and G1 case is also a recorded case (376 of 376 and
  123 of 123), which shows that the G1 capture reproduces the campaign's programs.
- **Nondeterministic tests.** Two recordings give the same case keys except
  `IntegerLiteralTest#generatedLiteralsHaveJavacsValue` (a jqwik property without a fixed seed: 300 random literal
  batches per run), whose cases are excluded unless another test also compiled them (300 cases), and the two
  `MultiFileCompilerTest$PathOverloads` tests, whose temporary file names carry random digits; the ledger removes
  those digits from file names (`Adr068Corpus.canonicalFileNames`). The external and Elci recordings have the same
  case keys from run to run.
- **The corpus itself is not checked in**: the in-repo recording is 10,213 sources, 11,534 cases and 33,645
  evaluations. It is reproducible with command 2; `068/corpus-b0.tsv` lists every case with
  its tags and the tests that compiled it.
- **In-repo julc-examples**: its validators are text blocks in its tests (plus `valueoriented/`), so they enter
  through recording (`julc-examples` test origins); the scan reads its on-chain files directly.

### Coverage gate

[`rejection-coverage-b0.tsv`](068/rejection-coverage-b0.tsv) checks the inventory against the hand-maintained
catalogue `julc-difftest/src/test/resources/adr068/rejection-sites.tsv`, which lists every code `diagnostics.json`
marks `emitted` (57) and every uncoded rejection site of the reference frontend (85, each a message pattern with its
source location). Each site is either reachable from source, and must then have inventory rows, or carries the
reason it is not a source rejection, and must then have none (an inventory row at such a site contradicts the
catalogue, F311); conversely, every inventory row must match a site. The baseline fails on any gap or
contradiction.

| Sites | Reachable from source | Covered | Not a source rejection | Uncovered | Uncatalogued rows | Contradicted |
|---|---|---|---|---|---|---|
| 142 (57 coded, 85 uncoded) | 116 (41 coded, 75 uncoded) | 116 | 26 (16 coded, 10 uncoded) | **0** | **0** | **0** |

**The gate passes.** The sites not reachable from source:

- coded: configuration rejections made before any source is read (`JULC0031`, `JULC0038`, `JULC0039`, `JULC0040`,
  `JULC0043`), target features PV11 always has (`JULC0033`), UPLC-generation invariants (`JULC0034`, `JULC0035`), the
  testkit's evaluation-target check (`JULC0036`), and the producer backend contract of ADR-056/059 for non-Java
  producers (`JULC0044`–`JULC0050`);
- uncoded: rejections another check makes first (`break` outside a loop in `PirGenerator`, a non-literal `byte[]`
  element, duplicate records, named types and sealed interfaces within one unit, type arguments on a type
  variable), and defensive checks no source reaches (an unknown switch variant, a lambda without a body, an
  incomplete recursive type, a lone backslash in a string, which JavaParser's lexer rejects first).

The 41 fixtures of `Adr068RejectionFixturesTest` (`julc-compiler/src/test/resources/adr068/rejections/`) compile,
through a public entry point, each source-reachable site the suite did not reach that way before (the `throw`,
`null`, try/catch and `synchronized` predicates, `do`/`while`, method references, functional calls, `this`, `super`,

- **What was made stable.** JavaParser appends its own stack trace to a parse problem (cut at `Problem stacktrace`);
