## Commands

```sh
# 1. The full suite (also the reference run of I1's gate).
./gradlew test --offline --continue --rerun

# 2. Record the corpus: every source the julc-compiler, julc-stdlib, julc-testkit, julc-difftest and julc-examples
#    test runs compile through a JulcCompiler entry point or JavaLibraryProvider.
./gradlew :julc-compiler:test :julc-stdlib:test :julc-testkit:test :julc-difftest:test :julc-examples:test \
    --offline --continue --rerun -Pjulc.corpus.record=build/julc-corpus

# 3. Capture the G1 fixed-seed corpus, then compile, run and scan; writes adr/evidence/068/.
./gradlew :julc-difftest:adr068Baseline -Padr068.corpus=build/julc-corpus -Padr068.external=../julc-examples --offline
```

`-Pjulc.corpus.record` also works on a plain `./gradlew test`: the property is passed only to the five modules'
test tasks. Step 3 depends on `adr068G1Capture`, which runs the G1 property's seed and arbitraries and writes
`julc-difftest/build/adr068/g1-fixed-seed.txt`. `-Padr068.threads=<n>` sets the compile parallelism (default:
cores − 2); `-Padr068.out=<dir>` writes elsewhere.

Not run here, recorded as commands for their owners (D4: the external repositories are not modified):

```sh
# External julc-examples against this checkout's snapshot, through the Maven-local override of ADR-041 (the
# examples' build file is not edited). <sha>: the 7-character hash the build appends (read it from ~/.m2).
./gradlew publishToMavenLocal --offline
(cd ../julc-examples && ./gradlew clean test --refresh-dependencies \
    -I ../julc-068-m0/adr/evidence/041-local-examples.init.gradle -Djulc.localVersion=0.1.0-pre20-<sha>-SNAPSHOT)
# Elci's smoke and custom-library: in the Elci checkout, against the same Maven-local snapshot, with Elci's own
# smoke command; its pool is the JavaLibraryProvider entry point, which command 2 records when run there with
# -Djulc.corpus.record=<dir> on the test JVM.
```

The external examples' on-chain sources are, however, read by the equality scan (step 3).

Notes:

- **Recorded cases are the corpus's bulk.** A case is a `case.txt` (entry point, method, stdlib lookup, target,
  source-map flag, disabled rules, source and resolved-library digests) keyed by its SHA-256; the same inputs
  generated by the ledger (a `.diffcase`, a G0 or G1 program) have the same key, so every G0 and G1 case is also a
  recorded case (376 of 376 and 123 of 123), which shows the G1 capture reproduces the campaign's programs.
- **Nondeterministic tests.** Recording twice gives the same tree except for
  `IntegerLiteralTest#generatedLiteralsHaveJavacsValue` (a jqwik property without a fixed seed: 300 random literal
  batches per run), whose cases are excluded unless another test also compiled them (300 cases), and
  `MultiFileCompilerTest$PathOverloads`, whose temporary file names carry random digits; the ledger removes those
  digits from file names (`Adr068Corpus.canonicalFileNames`).
- **The corpus itself is not checked in**: recorded, it is 10,078 sources (about 7 MB compressed). It is
  reproducible from B0's sources with command 2; `068/corpus-b0.tsv` lists every case with its tags and the tests
  that compiled it.
- **In-repo julc-examples**: its validators are text blocks in its tests (plus `valueoriented/`), so they enter
  through recording (`julc-examples` test origins); the scan reads its on-chain files directly.
- **Unreplayable**: 7 recorded cases were compiled with a test's own stdlib lookup (`StdlibIntegrationTest$1`, 5; `CompositeStdlibLookup`, 2). The ledger cannot rebuild the lookup, so their cells are `U:` and they are counted apart; they are not in the rejection inventory.

## The D13 ledger (reference rows)

Files: [`ledger-b0.tsv`](068/ledger-b0.tsv) (one row per case), [`ledger-b0-semantic.tsv`](068/ledger-b0-semantic.tsv)
and [`ledger-b0-budget.tsv`](068/ledger-b0-budget.tsv) (one row per harness run), [`totals-b0.tsv`](068/totals-b0.tsv).

- Per case and level (`NONE`, `BASELINE`, `PV11_SAFE`, `PV11_COSTED`): `A:<FLAT sha256, 32 hex>:<bytes>`, or, for a
  `JavaLibraryProvider` case, `A:<sha256 of its exports, materialized PIR, schemes, types and named
  definitions>:-`; a rejection is `R:<code>@<line>:<column>`, or `R:uncoded/<exception>/<message sha256/16>@…`.
- The source-map column is the count and digest of the located terms (index, file name, line, column, fragment)
  of a source-map compile; ADR-068 I7 compares against it.
- Ledger metadata (I11): `ledger:LedgerTypeProvider` digests the empty provider's `types()` and
  `namedDefinitions()`; one `ledger-source` row per ledger file digests the entries of the types it declares.
- The runnable cases (every `.diffcase`, G0's 376 programs × 4 inputs, G1's 150 fixed-seed tries) were
  run by `DiffRunner.standard()` (the Java VM at every level). Semantic observations (kind, value, traces,
  failure detail, verdict) and budgets (CPU, memory, script bytes) are separate files, as D13 requires.

## The D6 equality call-site scan

Files: [`equality-scan-b0.tsv`](068/equality-scan-b0.tsv) (hits), [`equality-scan-b0-type-variables.tsv`](068/equality-scan-b0-type-variables.tsv),
[`equality-scan-b0-nested-collections.tsv`](068/equality-scan-b0-nested-collections.tsv) (#297), and
[`equality-scan-b0-totals.tsv`](068/equality-scan-b0-totals.tsv), which also lists the operation table.

The predicate is `org.julclang.compiler.frontend.javac.ArrayIdentityEquality` and the operations
`EqualityOperations` (julc-compiler, unit-tested, for M3). javac (`ToolProvider.getSystemJavaCompiler()`,
`analyze()`, `Trees`, `-source 21 -proc:none`, the test class path) reads each in-repo unit on its own, and the
external examples' on-chain files (those with a validator or `@OnchainLibrary` annotation) as one project. A unit
javac rejects as written is retried with the dialect's implicit imports added on its first line
(`accepted+imports`); a unit javac still rejects (BigInteger operators, say) is `partial`, and only sites whose
compared type javac attributed without error are reported from it.

| Corpus | Units accepted | accepted+imports | partial | Hits |
|---|---|---|---|---|
| In-repo (recorded sources, stdlib, ledger, fixtures, in-repo examples, `.diffcase`) | 4,050 | 4 | 5,939 | 11 rows, 6 distinct sources (below) |
| External `../julc-examples` (57 on-chain files) | 54 | 0 | 3 | 125, all `.equals` on `byte[]` |

In-repo hits (each `.diffcase` source is also a recorded source, so it appears twice in the file):

- `diverge-t5-record-with-byte-array-equals`: `Holder.equals` on a record with a `byte[]` component (T5);
- `diverge-t31-explicit-equals-always-true` and `-by-sign`: `P.equals` on a record that declares `equals`, not on
  the allow-list (T31);
- `agree-equals-unknown-switch` and `-ternary`: `.equals` at the static type `java.lang.Record`, which the check
  cannot resolve (an `AGREE` pin today, a `JULC0087` rejection under D6 as written);
- `BigIntegerCompatTest$EqualsMethod#equalsOnByteStringField` (partial: the unit uses implicit imports and a raw
  `PlutusData` argument): `datum.beneficiary().equals(redeemer)` on `byte[]`.

External hits, by file: `UVerifyV1` 24, `CfLotteryValidator` 14, `CfBetValidator` 12, `CfAuctionValidator` 10,
`LinkedListLib` 9, `CfPriceBetValidator` 7, `UVerifyProxy`, `CfProxyValidator`, `CfIdentityValidator` 5 each,
`UVerifyTxLib`, `UVerifyFeePot`, `CfStorageValidator`, `CfAnonymousDataValidator` 4 each,
`CfPaymentSplitterValidator` 3 (lines 51, 83 and 94, as D6 cites), `CfEscrowValidator` 3, and 9 more files with 1
or 2. Every external hit is `byte[].equals(…)` (`Object.equals` at `byte[]`).

Type-variable sites: 5, all in generic library code (`TypedMapLib.lookup`, `member`, `insert`, `remove` on `K`,
and `PlutusDataHelper.encodeJulcMap`); no Java call site in the corpus binds a compared type variable outside the
operation table. Nested JuLC collection sites (#297): none.

Approximations, as the coordinator allowed for M0:

- **Generic methods.** A comparison on one of the enclosing generic method's own type variables is listed as a
  type-variable site, not a hit. Calls of such a method from the same unit are checked at the type javac binds to
  that variable when it is a parameter's declared type (one level, no propagation through callees or lambdas;
  M3 computes the summaries). Calls of `TypedMapLib`'s generic methods are in the operation table, so they are
  checked at the bound key type.
- **Raw collections** (`((JulcMap) (Object) value).containsKey(policyId)` in `ValuesLib`): the compared type is the
  argument's static type.
- **Explicit `equals` of a class-file record** is recognised by javac's flags (a record's implicit `equals` is
  `final` in the class file; a declared one is not unless written so); source records use the tree.

## Determinism

- Two recordings (command 2 twice) give the same 11,196 case keys except the 300 cases of
  `IntegerLiteralTest#generatedLiteralsHaveJavacsValue` per run and the temporary file names of
  `MultiFileCompilerTest$PathOverloads`, both handled as described under [Corpus](#corpus).
- The baseline over the first recording (13 compile threads) and over the second (one thread) wrote byte-identical
  files, all eleven.
- Two things made early runs differ and are now removed from what is digested: JavaParser appends its own stack
  trace to a parse problem (cut at `Problem stacktrace`), and a PIR term's `toString` prints `byte[]` identities
  (library cases are digested through `PirFormatter`, and an identity hash in a description fails the run).
