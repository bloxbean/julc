# #22 library discovery cleanup and #118 decision gate

Base: merged `main` at `3d0e89a9` (PR #123).
Branch: `fix/22-library-discovery-118-decision`.

## Scope and invariants

Remove the redundant 13 `@OnchainLibrary` names from `JulcCompiler.STDLIB_FQCNS`.
Retain `Builtins`, which has no compiled library source and maps directly through
the stdlib registry. Both full compilation and `compileMethod` already add
library class FQCNs from their resolved compilation units to `knownFqcns`.
Do not alter source scanning, import precedence, classloader selection, library
compilation, lowering, diagnostics or public APIs. This is cleanup of the
existing source-discovery architecture, not a new compiler stage or language
feature. No new ADR is needed for the removal; ADR-032 governs the separate O12
decision below.

## #118 decision: no additional implementation required

`MathLib.expMod(base, exponent, modulus)` already delegates to
`Builtins.expModInteger`. No distinct supported source contract has been
introduced that needs another recognition rule. Therefore the issue's decision
gate selects no additional implementation. No new O12 rule is enabled at any
optimization level.

Ordinary `MathLib.pow(base, exponent) % modulus` is not equivalent:

- `(2 ^ -1) % 5` returns 1 under the existing MathLib source contract; explicit
  modular exponentiation returns the inverse, 3.
- `(2 ^ -1) % 4` returns 1; explicit modular exponentiation fails because no
  modular inverse exists.
- Modulus failure behavior belongs to the original operation and must not be
  replaced by a different builtin's failure contract.

The existing [O12 research evidence](032-cost-use-rewrite-deferrals.md#o12--ordinary-powmod-is-not-expmodinteger)
continues to apply. A new source abstraction would need a new explicit decision
and full boundary/strictness/target evidence. Tests here protect the rejection,
not enable a new semantic transformation. #118 can close as no additional
implementation required when this decision is accepted.

## Regression evidence

`LibraryDiscoveryCleanupTest` covers:

- Full compilation and `compileMethod` importing all 13 formerly hardcoded
  libraries, wildcard imports, and implicit stdlib imports.
- Equivalent generated bytes across import styles and expected VM results for
  the executed method.
- Explicit custom library sources plus Builtins with no supplied stdlib sources.
- Indexed classpath discovery of a custom library and its transitive same-package
  dependency through both entry points, plus the expected evaluated result.
- Pre-cleanup method and validator FLAT bytes, captured at `3d0e89a9` before the
  production change and stored in `library-discovery-pre-cleanup.txt`. The tests
  passed on the original compiler and match those bytes after cleanup. These
  representative fixtures are not a universal claim that every possible script
  was byte-compared.

`ExpModDecisionGateTest` compares BASELINE with PV11_SAFE and PV11_COSTED on
Java and Truffle using the pinned `cardano-node-11.0.1-plutus-v3-pv11` cost
profile. It checks ordinary inputs, negative exponents, non-invertibility,
zero/negative/one modulus, and zero base/exponent. Each before/after pair must
preserve results, exact failure messages and traces. Independent expected-value
assertions distinguish the source contracts, and structural checks ensure only
the explicit API contains `ExpModInteger`. Existing O13 boundary/failure tests
remain unchanged. No backend or cost model changes are made.
