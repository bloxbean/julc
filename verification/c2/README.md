# Milestone C.2 verification evidence

This module tests the strict Lean encoders and decoders generated by
`julc verify init` for JuLC booleans, optional values, lists, maps, and nested
nonrecursive combinations.

It contains two real JuLC projects:

- `fixtures/spending` exercises container fields in a spending datum; and
- `fixtures/minting` exercises the same forms in a minting redeemer.

`CodecTests.lean` checks successful concrete round trips and malformed values,
including wrong boolean and optional constructors, bad list items, bad map
keys and values, duplicate map-key preservation, and a nested failure path.

Run the complete evidence suite from the repository root:

```bash
verification/c2/scripts/verify.sh
```

The first run needs network access so Lake can acquire the exact dependency
revisions embedded in the generated workspaces. Later runs reuse each ignored
workspace's `.lake` directory. Success ends with:

```text
ESTABLISHED: Milestone C.2 generated container codecs and workspaces compile
```

This establishes schema/codec compatibility and workspace reproducibility. It
does not establish a contract-specific security property; generated workspaces
still require a reviewed property, theorem, and vulnerable negative control.

## Map semantics

Generated `JulcMap` values are ordered association lists. Duplicate keys are
accepted and preserved because this is what JuLC's `UnMapData` lowering and
`JulcAssocMap` representation do. No Java `Map` uniqueness assumption is added
by the verifier. Equality in Lean properties is structural association-list
equality, not extensional map equality: entry order and duplicates matter even
when two maps have the same lookup behavior.
